## 🟢 АКТИВНЫЙ ТРЕК: Мобильная адаптация (приоритет №1)

**Цель**: Адаптировать сайт под 320–414px (mobile-first для всех ключевых экранов).

**Обоснование**: 70–80% аптечного трафика в РФ — мобильный. Mobile-first индексация Google + YMYL-критерии = без адаптации проигрываем aptekamos в выдаче. До парсеров — потому что не нужно дважды переделывать одни и те же компоненты.

### Экраны под адаптацию
1. Home — мобильное меню (гамбургер/sticky), hero, поиск
2. Search — фильтры в bottom-sheet, мобильный список результатов
3. MedDetail — переверстать 2-колоночный grid в 1 колонку, sticky-блок «Цена + На карте», bottom-sheet для аналогов

5. PharmacyDetail
6. Каталог / категории

### Технические принципы
- Mobile-first вёрстка (375px → расширяем)
- Tap-zone ≥ 44×44 px
- Sticky-search в шапке
- Tailwind responsive utilities (`sm:`, `md:`, `lg:`) — не переписываем, а добавляем мобильные базовые стили
- Сохраняем существующую визуальную ДНК (emerald + slate, шрифты, скругления)

## 🟡 СЛЕДУЮЩИЙ ТРЕК: Парсеры аптечных сетей (после мобильной адаптации)

**Цель**: Заменить mock-цены в `backend/api/__init__.py` на реальные данные с топ-4 аптечных сетей РФ.

### Архитектурное решение

**Парсер крутится на нашей VM (`89.169.137.36`) как отдельный сервис в `docker-compose.yml`** (не на отдельной VM, не за прокси — пока не понадобится).

- ~50 запросов/час суммарно по всем 4 сетям при топ-1000 SKU × 4 сети × раз в 2 часа → меньше 1 запроса в минуту на сеть → никакого риска бана
- Если бан произойдёт (вероятность низкая) — переедем на отдельную VM или Smartproxy за полдня
- Прокси нужны только для 366.ru / Stolichki / Samson (DDoS-Guard + hCaptcha) — их в фазе 1 не парсим

### Целевые сети (топ-4 = ~75% рынка)
| Сеть | Защита | Метод парсинга |
|---|---|---|
| **Apteka.ru** | Открыт | `window.__INITIAL_STATE__` в HTML — Redux-стейт со всеми ценами/аптеками/наличием за 1 HTTP-запрос |
| **Еаптека** | Открыт | sitemap.xml + JSON-LD из HTML карточек |
| **ГорЗдрав** | Открыт | sitemap.xml + HTML парсинг |
| **ZdravCity** | DDoS-Guard (мягкий) | `requests.Session()` с cookie-jar — DDoS-Guard выдаёт `__ddg*` cookies при первом запросе и пропускает |

Защищённые (не парсим в фазе 1): 366.ru, Stolichki, Samson, Rigla.

### Логика статусов наличия (фаза 1, парсинг) — РЕШЕНИЕ ПОЛЬЗОВАТЕЛЯ 2026-05-15
**Бейджи строго бинарные**: "В наличии" / "Нет в наличии". Никаких "Мало", "Много", "По предзаказу".

UX-логика:
- Аптеки **С** препаратом → видны на карте/в списке + зелёный бейдж "В наличии" + цена
- Аптеки **БЕЗ** препарата → НЕ отрисовываются для данного SKU (фильтр на бэкенде по `availability=true`)
- Если у SKU **ноль аптек с наличием** → общий статус карточки "Нет в наличии" (как сейчас работает `force_empty_stock`)

Никаких градаций — парсенные данные не дают надёжной точности, меньше визуального шума, меньше юр-риска.

### Логика количества (фаза 2, прямые подключения)
Когда аптека выгружает данные напрямую (1С-интеграция, обещанная B2B-фича) — тогда показываем **«в наличии: N шт»**. Поле `med_source` в записи цены:
- `med_source: "scraper"` → только наличие, без числа
- `med_source: "direct"` → точное количество + бейдж «Актуально: N шт»

## Решения, сохранённые в этой сессии

1. **Не скрейпим aptekamos** — высокий юр-риск (БД-права + ФАС + Росздравнадзор)
2. **Не парсим Я.Маркет** — Яндекс наш поставщик API карт, не подгаживаем
3. **Источник данных — сайты сетей напрямую** через sitemap + JSON-LD + `window.__INITIAL_STATE__`
4. **Affiliate (Admitad)** — параллельный монетизационный слой, не замена данным
5. **Мобильная версия — раньше парсеров** (трафик 70–80% mobile, SEO mobile-first)
6. **Бейджи количества — только для прямых подключений (фаза 2)**. В фазе 1 (скрейпинг) бейджи строго бинарные: "В наличии" (зелёный, только у аптек с препаратом) / "Нет в наличии" (общий статус карточки, когда ноль аптек с препаратом). Аптеки без препарата не отрисовываются для данного SKU. ([2026-05-15] подтверждено пользователем)

## Оперативные заметки

**Edge nginx + frontend recreate**: после `bash deploy/rebuild-frontend.sh` (rebuild + recreate frontend) обязательно делать `cd ~/aptekaa/deploy && docker compose up -d --force-recreate edge` иначе 502 (новый frontend получает новый IP в docker-bridge, edge кэширует старый).

**Docker buildkit**: если билд падает с `no space left on device` — `docker builder prune -af`. Disk /var/lib/docker обычно 3-4GB, проблема в buildkit cache.
